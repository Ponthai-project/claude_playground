## 1. 依頼

「Fable5.1がリリースされたので、特徴やFable5, Opus5との違いをまとめて。出力はグラレコ調のhtmlで」。
作業途中で「作業場所はClaude_playground配下のディレクトリでお願い」との追加指示。

## 2. 前提・制約

- 対象モデルは信玄の知識カットオフ（2026年5月）より後のリリースであり、`claude-api` skill の内蔵モデル表（2026-06-24キャッシュ）にも記載がない。**記憶からは一切書けず、全数値を web 調査で確定させる必要があった。**
- skill `graphreco-html` の規約に従う（単一HTML自己完結・CSP厳守・生成りパレット・図解7型・揺らぎフィルタ4帯・実レンダリング目視検分まで必須）。
- CLAUDE.md 項番10（資料の第一条）：図解の形式要件を満たすために本文・数値・比較対象を削らない。同時に「文章が厚いから図解不要」も禁じる。

## 4. 決定と決め手

**10節構成・ティアA・両重心同格で作成し、図解は9節に型を割り当て、移行チェックリストの節のみ「図示すべき関係の不在」を理由に図解なしとした。**
決め手は、**第一条（内容の正確さと充実は不可侵）を最優先し、図解の形式要件が内容を削る場面では図解側を譲る**方針を全節に一貫させたためである。ベンチマーク節で代表3指標に絞ったのは削減ではなく、直下の補足表に全10指標を残したうえでの役割分担である。

## 試行錯誤ログ

| 事象 | 原因 | 対処 |
|---|---|---|
| カード枠・付箋の手描き枠が一切描画されない | `body` に不透明な背景色があるため、`.card::before{z-index:-1}` が「ブロック背景」フェーズで塗り潰された。負の z-index 子は最近傍の重ね合わせ文脈（既定では root）の直後に描かれ、body 背景より下になる | `body{ position:relative; z-index:0 }` を追加し、body 自身を重ね合わせ文脈にした |
| Bash の heredoc（`cat >> ... << 'EOF'`）が `unexpected EOF` で失敗 | 長大な日本語＋HTMLをヒアドキュメントで渡した際にシェルが閉じ記号を見失った | Edit ツールでの追記に切り替えた。長文追記はツール経由が確実 |
| 狭幅レンダリングで文書が右へずれ、右端が切れて見えた | **誤検知**。計測用コピーに JS を仕込んで実測したところ `docScrollW == viewport` で横スクロールは存在せず、レンダラの実効ビューポート（`--width 420` 指定に対し clientWidth 492）と出力画像幅の食い違いによる見かけの現象だった | 誤検知と判明。ただし切り分け中に加えた `overflow-wrap:anywhere`（長い識別子・URL向け）、`min-width:0`、`minmax(min(400px,100%),1fr)` は堅牢性向上として残した |
| 上記の切り分けでフィルタ領域を `x=-1.5% width=103%` 等へ絞った結果、カード枠が直線の帯に見えた | **これも誤検知**。角を含まない中央部を拡大していたため。角を含む領域で見ると丸角も揺らぎも正常 | 領域はスキル規定値（`-l`: x=-5% y=-15% width=110% height=130%）へ戻した。**拡大検分は必ず角を含む範囲で行うこと** |
| `dna` シンボルの初版が二重らせんに見えず「聴診器」状になった | 2本の鎖を左右非対称の Q 曲線で描き、交差が潰れた | 中心線 x=40 を軸に左右対称の Q 曲線2本＋横棒6本へ描き直し、交差点を y=10/38/66 に固定した |

## C9（目視・理解しやすくなったか）

| 節 | 型 | 判定 |
|---|---|---|
| 01 | 対比 | 「同一モデルで安全策のみ違う」という関係は文章では二度読みが要る。左右2枠＋中央の等号で一目になった。情報の欠落なし |
| 02 | 比率 | 3指標のモデル間量比が一目。全10指標は直下の表に完全収載しており、図解のために削った数値はない |
| 03 | 因果 | 「据え置き＋キャッシュ読み取りのみ低下」がなぜ25〜45%減に繋がるかは、原因3つ→結果1つの収束で初めて掴める |
| 04 | 対比 | 「通っていた書き方→400」の対応が左右で対になり、どのコードが壊れるかが一目。詳細はカード3枚に全量残置 |
| 05 | 階層 | 追加5件の内訳（ベータ3／価格1／来歴1）が入れ子枠で把握できる |
| 06 | 位置づけ | 性能とコストの相対配置は文章では伝わらない。Fable 5 の「高いのに負ける」位置と Fable 5.1 の逆転が図で初めて見える |
| 07 | 流れ | 6つの挙動変化が「エージェントループのどの段で効くか」に紐づく。表だけでは順序が見えない |
| 08 | 因果 | 誤検知の減少と「脆弱性の発見が可能に」の因果が明示される |
| 09 | 比率 | 3件の科学成果の倍率が縦バーで比較でき、金星の「短いほど細かい」の反転も注記で担保 |
| 10 | 図解なし | **順不同で独立に点検する確認項目の一覧であり、順序・因果・位置づけ・量比・対比・階層のいずれの関係も含まない。** 図示すべき構造が存在しないため図解を置かなかった（「本文で説明したから」を理由としていない） |

同一型が3節以上ある型はなく（最多は対比・比率・因果の各2節）、図の形も節ごとに変えている（01は3枠横並び、04は左右リスト＋矢印3本／03は原因3→結果1、08は原因2→結果1／02は横バー、09は縦バー）。新規作成のため改訂前との突き合わせは対象外。

## memory昇格候補

- 負の z-index の `::before` で手描き枠を描く場合、`body` に不透明背景があるなら `body{position:relative;z-index:0}` が必須。→ グラレコ全案件で再発するため昇格を検討する。
- レンダリング画像の拡大検分は、枠の欠けを見るなら必ず**角を含む範囲**を切り出す。中央部だけを見て「枠が直線になった」と誤判定した。
