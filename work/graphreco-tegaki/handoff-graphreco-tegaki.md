## 1. 今回の診断と、規約の建て替え

### 1-1. 診断（山本勘助）

現行規約は「各節に線画イラスト**最低1点**」——**点数の規約**であった。**点数の規約は点数で満たされる。**
48pxのアイコンを見出し右端に1個貼れば形式上は合格し、現に7件すべてがそうなっていた。しかも
05〜08・10節は点数規約すら満たさぬまま提出されていた。

**→ 計量単位を「点数」から「型 × 占有面積 × 接続関係」へ取り替える**、という筋立てで着手した。

### 1-2. 図解7型と判定順序

| 型 | 判定条件（見出し＋サブ一文のみ走査） |
|---|---|
| T1 対比 / T2 流れ / T5 因果 / T4 比率 / T6 位置づけ / T3 階層 / T7 場面 | 詳細は `figure-patterns.md` |

- **走査順序：T1 → T2 → T5 → T4 → T6 → T3 → T7**（first match wins）。番号順ではない。
- **T3を後段に下げた**理由：T3の判定語にあった「3つの〜」「N個の〜」は見出しの常套句で、
  中身が手順でも因果でも構成でも等しく拾う。**数の列挙は構造を規定しない**ため判定語から削除し、
  T3を「他のどの構造にも当たらない構造的分解」の受け皿として最後に置いた。
- 選んだ型は `<div class="fig-block" data-fig-type="対比">` の形でHTMLに記録する（機械確認の唯一の鍵）。
  語彙は7語のみ（対比／流れ／因果／比率／位置づけ／階層／場面）、表記揺れ禁止。

### 1-3. 廃止した条項（実データで破綻したもの）

- **「同一型の使用は全節数の1/3以下」→ 廃止。** 実データ（29節・3ファイル）でT3が38%、
  hooks単体で50%を占め、**素直に分類しただけで違反する**。このまま書けば実装者は
  「合格させるために型を偽って申告する」最悪の運用に流れる。**型の偏りは資料の内容の性質であって欠陥ではない。**
  → 代わりに **「相異なる型が3種以上」の下限のみ**を課す（図解を置いた節が3節未満なら課さない）。
  T7（場面）の1/3上限のみ維持（逃げ場を塞ぐため）。
- **`checklist` 旧①-3「symbol点数が節数以上」→ 廃止。** 数えていたのが `<symbol id=` すなわち
  **定義の数**であり、定義だけ増やして使わなければ通る。現に `svg-snippets.md` に11点定義されながら
  実使用は5点で、**この検査は目的を一度も果たしていなかった。** 目的（使い回しの防止）はC9の目視へ統合。

## 2. 【最重要】第一条 —— 殿の二度のご指摘で規約の芯が入れ替わった

**ここが今回の本質である。型の話より先にこれを読むこと。**

### 2-1. 一度目のご指摘（内容の不可侵）

> 図の個数とかは本質ではなくて、理解しやすい資料っていうのが本質なわけ。
> 内容が正しくかつ充実しているのなんて大前提で、それをグラフィックにこだわるあまり蔑ろにするなんてありえないから。

**信玄の誤りはこうであった。** 勘助の診断「点数の規約は点数で満たされる」は正しかった。だが信玄は
それを**型の規約に置き換えただけ**で、**型の規約もまた型で満たされる**ことに思い至らなかった。
「各節に図解必須」「部品1点以上」「占有幅60%以上」「高さ200px以上」——形式要件の束を作り、
**「その結果として資料が分かりやすくなったか」を一度も問うていなかった。**

**現に事故が起きた**（見本02節。詳細は 4-2）。

### 2-2. 二度目のご指摘（裏返しの禁止）

> 言っておくけど文章長文を書いているから図はいらないっていう解釈はやめてね

第一条を据えた反動で、**今度は「文章を厚く書いたから図は省いてよい」という逃げ道**が生まれかけた。
それを許せば、本件の出発点である「**文字パネル＋マーカー下線だけで済ませるな**」の真逆へ回帰する。
**過去7件が陥っていたのは、まさにその状態であった。**

### 2-3. 確定した第一条（`figure-patterns.md` の冒頭・判定表より前に配置済み）

**A. 図解が内容を侵すな**
1. 資料の目的は読み手が理解しやすいこと。**図解は手段であって、図解を入れること自体は目的ではない。**
2. **内容の正確さと充実は不可侵。** 図解の要件（型・部品数・占有幅・高さ）を満たすために、
   本文・数値・注記・比較対象・既存の表現を**削ってはならない。**
3. **「部品1点」は加算の要件であって置換の口実ではない。**
4. 判定の問いは「規約を満たしたか」ではなく「**その図があることで、無い場合より理解しやすくなったか**」。

**B. 文章が図解の不在を正当化するな**
1. **「文章を長く書いているから図はいらない」という解釈は禁じる。**
2. 判定基準は**文章の量ではなく「図示すべき関係の有無」**。
3. **長文であるほど、むしろ図解が要る。** 長い説明を読み下さねば掴めぬ構造こそ図が見せるべきもの。
   **文章が厚いことは図解を省く理由ではなく、図解を要する徴候である。**
4. 節が**順序・因果・位置づけ・量比・対比・階層**のいずれかを含むなら、**文章が何行あろうと図解を置く。**
5. 省いてよいのは**図示すべき関係が無い節のみ**（単なる定義・引用・一文の宣言・短い注記）。
6. C9に書ける根拠は**「関係の不在」の説明のみ。「本文で厚く説明したから」は不合格。**

**AとBの関係**：どちらか一方に倒して楽をすることを禁じる。**両立の道を探すのが実装者の仕事**である。
02節の解（既存情報を一つも削らず、バー幅も狭めず、見出し直下に一行だけ添えた）がその実例。

### 2-4. 第一条から派生した是正

- **「全節に図解必須」を撤回。** 数の下限を課すこと自体が第一条と衝突する。
- **C1（節数と図解数の突合）を「数の強制」から「差分をC9の点検対象として洗い出す」役割へ変更。**
- **C6の分母を「総節数×3」→「図解を置いた節数×3」へ。** 総節数のままでは
  **図解を減らすほど不合格に近づく**という第一条と逆向きの圧力がかかっていた。
  あわせて「C6は枠だけ置く事故を捕まえる**粗い網**にすぎず、本体は型ごとの必須構成要素とC9」と明記。
- **「手段を必須要件として書いていた」箇所を全型で是正。** 例：T4の「**軸または基準線**」→
  「**基準（何と比べているか）が読み手に伝わること**」を要件とし、軸線・目盛り・比較対象の明示・
  対の並置を**手段の例示**へ格下げ。T1の矢印、T2・T5の矢印、T3の入れ子枠も同様に「関係が一目でわかる明示」へ統一。
  **あわせて「原文の精度が曖昧（超・約・≈等）な場合、要件を満たすためだけに断定的な目盛りを描くな」を明記**
  （無い精度を在るように見せるのは第一条Aに反する）。
- T6・T7は据え置き（T6の軸は型の定義そのもの、T7の「吹き出しかキャプション」は既に二択で手段を固定していない）。

## 7. 検証の作法（前回から継続。**必ず守る**）

**実レンダリングでの目視検分は必須。**「フィルタを書いたから手描きになったはず」は検証ではない。

```
python C:\Users\topge\.claude\bin\render_html.py --in <入力HTML> --out <出力PNG> --width 1280 --height 6500
python C:\Users\topge\.claude\bin\crop_image.py --in <入力PNG> --out <出力PNG> --left <L> --right <R> --top <T> --bottom <B> --scale 3
```

- **`--height` は 6500 を使う。** 2400ではEdgeのheadless screenshotがビューポート高でクリップされ全節が写らない（実測で判明）。
- 生成したPNGは必ず Read ツールで開いて**目で見る**。出力名は固定して上書きし、連番を振らない。
- 揺らぎの検分は「88〜120pxの部品」「300px前後の枠」「900px前後のカード枠」の**三帯すべて**を見る。
- **クロップの範囲を確かめてから判断する**（6-1の轍）。節全体が写っているか。
- **報告では、実機で確認した事項と論理的に推論しただけの事項を必ず区別する。**
